# 実装計画: 凹凸（Curvature）陰影ソースにおける3MFエクスポート高速化とフリーズ解消

## 概要
Mac環境および大容量メッシュにおいて、陰影ソースを「モデルの凹凸（Mesh Curvature）」に設定して3MFエクスポートを実行した際、進捗78%（レイヤー整合テクスチャを変形適用中）で数分間ブラウザが固まる（フリーズする）不具合を根本解消します。

### 問題の根本原因
1. **数億回の一時文字列生成とGC（ガベージコレクション）多発**:
   - `sampleFn` 内で1頂点ごとに125回、`${gx + dx},${gy + dy},${gz + dz}` というテンプレート文字列を生成して `Map.get()` を実行していた。
   - スライス後メッシュ（100万〜200万頂点）で数億個の一時文字列オブジェクトが量産され、V8およびJavaScriptCoreのGCが連続ストップ・ザ・ワールドを発生。
2. **過剰な近傍セル探索（125セル）**:
   - `dx, dy, dz` が -2..2 の125セル探索になっており、計算回数が過剰。
3. **メインスレッド同期実行によるUI完全停止**:
   - 長時間のループ中に `yieldFrame()` が挟まれておらず、ブラウザの再描画やイベントループが完全停止して「応答なし」状態に陥っていた。

## 修正計画

### 1. 空間グリッドの TypedArray 化（Head-Next リンクリスト）
- JavaScript の `Map` および文字列キー `${gx},${gy},${gz}` を完全撤廃。
- 頂点バウンディングボックスからグリッド解像度（$N_x, N_y, N_z$）を算出し、`head`（`Int32Array`）と `next`（`Int32Array`）の2本の固定長配列のみで空間ビンを管理する「Forward-Star / リンクリスト方式」を採用。
- メモリ割り当ては最初の2本のみ（数MB以下）、アロケーションおよびGC負荷は完全ゼロ。

### 2. 探索範囲の適正化（27セル化）
- グリッドのセルサイズ（`CELL`）を適正化し、探索範囲を `dx, dy, dz` 各 -1..1（計 27セル）に集約。
- 計算回数を従来の 1/5（約20%）に激減。

### 3. バージョン更新とドキュメント
- `js/version.js` を `1.5.18` → `1.5.19` に更新。
- `CHANGELOG.md` に修正内容を詳細記載。

## 検証計画
- `node` スクリプト等による空間グリッド探索の速度比較（ビフォー・アフターのベンチマーク）。
- 頂点曲率のサンプリング結果が同一であることを検証。
