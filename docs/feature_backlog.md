## 📌 機能詳細

### FEAT-01: カラー3MFの編集・読み込み対応 (Color 3MF Import & Editing Support)

- **ステータス**: 検討中（実装可否・要件定義フェーズ）
- **登録日**: 2026-10-04

#### 1. 背景・ユースケース
- **想定ユースケース**:
  - 既にスライサー（Bambu Studio, OrcaSlicer, PrusaSlicer 等）やCADでカラー（白黒など）が割り当てられている3MFファイルを読み込み、その既存の配色を維持したまま、特定の部分に別の色（赤や青など）のテクスチャ・模様を追加して再度マルチツール3MFとして書き出したい。
- **現状の挙動**:
  - 現在の [js/stlLoader.js](file:///Users/phaizmithriln/Desktop/BumpMesh_color/js/stlLoader.js) (`parse3MF`) は頂点座標 (`<vertex>`) と面 (`<triangle>`) のみを抽出して単一の `BufferGeometry` に結合している。
  - 3MF内のカラー定義（マテリアル、`<m:colorgroup>`、ファセットペイント属性、頂点カラー、複数パーツ構造）は読み込み時に破棄され、無地の形状モデルとして扱われる。
  - 一方でエクスポート側（[js/exporter.js](file:///Users/phaizmithriln/Desktop/BumpMesh_color/js/exporter.js) の `exportMultiColor3MF`）は各ポリゴンに Tool 1〜8 を割り当てるマルチツール3MFの書き出しに完全対応している。

#### 2. 実装アプローチ案
- **案A: 3MFカラー属性のインポートと既存色の引き継ぎ**
  - 3MFパーサーを拡張し、Bambu/Prusa 形式のファセットペイント情報（`<triangle ... p:paint="..."/>` や `<m:colorgroup>`）を解析して各面の既存 Tool ID（またはカラーコード）を読み取る。
  - 読み込んだ既存色を「ベースカラー」として保持し、テクスチャが投影されない領域・マスクされた領域には元の色を自動割り当てする。
  - テクスチャが適用される領域のみ、新しい色（Tool 3, Tool 4等）で上書きする。
- **案B: 複数オブジェクト / パーツ構造の保持**
  - 3MF内の `<component>` や個別 `<object>` を結合せずに別メッシュとして保持し、パーツごとにテクスチャ適用やツール割り当てを行えるようにする。
- **案C: テクスチャ側でのレイヤー合成（デカール / スタンプ）**
  - 3Dモデル側ではなく、2Dテクスチャ生成側で「白黒ベース画像」に対して赤・青の透過PNG等を特定位置にスタンプのように配置できるレイヤー機能を提供する。

#### 3. 技術的課題・留意点
- **スライサー仕様の差異**:
  - PrusaSlicer、Bambu Studio、OrcaSlicer で3MFへのカラー書き込み仕様（メタデータ構造、カスタムXMLタグ、圧縮コンポーネント）に差異があるため、主要スライサーの出力を網羅的に解釈する必要がある。
- **テクスチャ投影と既存ペイントの境界処理**:
  - テクスチャによって変位（Displacement）や色分けが発生する領域と、既存のペイントを残す領域の境界をどう判定・補間するか（Exclusionペイントブラシとの連携など）。
- **マニホールド性とトポロジー**:
  - 既存の色分け境界を維持しながらメッシュ分割を行うと非多様体（non-manifold）エラーが生じやすいため、現在のファセットペイント（単一シェル方式）を崩さないようにTool番号をマッピングする必要がある。
